# Catalog

Not built. Proposal.

The catalog shows everything the studio owns. One source, two readers: a page for the human, data for the agents. A crew that can see the library reuses instead of re-inventing.

## The source: cards beside code

Every library item has a `*.card.ts` next to its code. The card is typed TypeScript, so a missing field is a build error.

```ts
// packages/library/src/card.ts
export type LibraryKind =
  | 'character' | 'pose' | 'expression' | 'wardrobe' | 'prop' | 'background'
  | 'shot' | 'sound' | 'motif' | 'voice' | 'symbol';

export interface LibraryCard {
  id: `${LibraryKind}.${string}`;
  kind: LibraryKind;
  name: string;
  summary: string;                      // one plain line
  origin: { video: string; beat?: string };
  module: string;                       // '@studio/library/characters/bean'
  preview: Preview;
  tags?: string[];
}

export type Preview =
  | { kind: 'frame'; draw: (T: number) => void; seconds?: number; size?: [number, number] }
  | { kind: 'audio'; seconds: number }
  | { kind: 'voice' }
  | { kind: 'shot'; sample: ShotSpec }
  | { kind: 'symbol'; states: string[] };
```

## The build

`wm catalog:build` (Node, in `packages/library`):

1. Globs `src/**/*.card.ts`, imports each, checks ids are unique and match their folder.
2. Renders each preview headless (Playwright on a small catalog page that imports the library) into `dist/studio/catalog/<id>.png` or `.wav`. Deterministic, so the PNG hash is a cheap "did the look change" signal.
3. Computes `usedBy`: a grep of every video's `scenes/`, `script/` and `production/style-guide/visual-vocabulary.md` for the module path or `library:<id>`.
4. Writes `dist/studio/catalog.json`.

```ts
export interface CatalogEntry extends Omit<LibraryCard, 'preview'> {
  preview: { png?: string; wav?: string; strip?: string[] };   // paths
  usedBy: { video: string; where: string[] }[];
  params?: Record<string, string>;      // shot templates: the zod schema printed
}
export interface Catalog { built: string; libraryHash: string; entries: CatalogEntry[] }
```

## The human page

Part of the studio app ([studio-app.md](studio-app.md)) and published with the site at `/studio/catalog/`. One grid per kind. Each tile: preview, name, one-line summary, "used in N videos". Click: the card, the params table for a shot, the states for a symbol, the play button for a sound or a voice, and the usage list with links to each beat in that video's player at the right time.

Search by name, tag or kind. No numbers unless asked for.

## The agent data

Agents never read the TS cards. They read `catalog.json` through one command:

```
wm catalog                       # every entry, id + summary, one per line
wm catalog shot                  # one kind
wm catalog shot.visitorTry       # one entry as JSON, with params and preview paths
```

## How briefs cite catalog items

The producer's brief template gains one block, generated by `wm brief` ([coordination.md](coordination.md)):

```
LIBRARY (use these; do not redraw them)
- character.bean — Round figure with eyes, mouth and two arms. @studio/library/characters/bean
- shot.visitorTry — A visitor enters, tries the target, fails, sulks. params: visitor, target, on
- symbol.star — inner experience: lit = present, unlit = absent. Never: cognition, value.
Preview PNGs: dist/studio/catalog/<id>.png
A thing you need that is not here: stop and propose it (look, meaning, beat). Do not draw a local one.
```

The producer picks the entries by kind for the role: an animator gets characters, poses, props, shots and symbols; a sound engineer gets sounds and motifs; casting gets voices. The storyboard cites ids the same way, so a board that names `shot.checklist` compiles to that template.

## Why not a markdown list

The first production's vocabulary was a markdown table that one agent wrote and others read. It worked inside one video. Across videos the table would be copied and drift. A card beside the code cannot drift from the code, and the usage list is computed, so it is never stale.
